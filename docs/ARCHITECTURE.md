# Engine architecture and extension contracts

`strategy-api` is the shared contract JAR. `engine` owns order accounting, generic policy, sequencing and infrastructure. `example-twap`, `example-is` and `example-passive` are independently loaded strategy JARs. IS and Passive bundle the internal API-only execution helpers; no engine classes are bundled. Providers register through Java ServiceLoader metadata. Plugin discovery fingerprints artifacts for replay compatibility; deploy only trusted code because plugins execute in-process.

The Disruptor input ring reuses event slots. Producers normalize quotes, reports, configuration and explicit clock advances. One core thread owns all mutable financial state. Strategy-context methods enforce core-thread ownership. Terminal parents invoke `onStop` and release subscriptions; restarting replaces the strategy instance. Callbacks receive borrowed views and must finish promptly; never retain views, perform I/O, start background mutations, consult wall-clock time or use unrecorded randomness. Strategy scheduling uses logical nanoseconds and stable timer registration order. System clocks measure telemetry and produce recorded clock/overrun inputs; replay does not infer business time from a clock.

The price path updates reused quote state and visits subscribed parents without building an event object per quote. Configuration, management snapshots, order creation and output commands may allocate. Strategies own trajectory tolerance and opportunity decisions; the container checks every command regardless of its origin. It reserves all potentially fillable leaves, including cancel, replace and uncertain states. Stable-ID ledger chains avoid scanning unused capacity during financial/risk iteration; an indexed array retains constant-time child lookup. Final dispatch authorization rechecks readiness, quote freshness and policy after asynchronous queueing. Cancels/status use a separate priority queue. Subscription counts multiplex parents sharing an instrument/destination.

Policies can apply to engine, account, strategy, instrument, parent and destination. Applicable limits compose, with separate normal/cancellation token buckets and rolling/consecutive reject breakers. Accepted order intents are distinct from routed commands and execution acknowledgements. Fills are facts even when they breach intended exposure; the ledger records them and stops the affected parent. Corrections/busts update quantities using execution identity.

The asynchronous journal uses preallocated SPSC slots, direct batch writes, CRC32C, rotated segments, periodic force and complete-input transaction markers. Buffer exhaustion fails closed for new exposure. Replay compares recorded normalized inputs/outputs in sequence, suppresses live dispatch and checks checkpoint hashes. Hashes cover parent/child ledger and timers; command comparison is also necessary, and opaque strategy memory is not directly hashed. Explicit inputs and deterministic strategy code remain required.

## Writing a strategy

Implement `StrategyFactory` with name, validation, parameter descriptions and creation. Register its class in `META-INF/services/io.strategycontainer.api.StrategyFactory`; package it against `strategy-api` without bundling engine implementation classes. Configuration POJOs use builders/immutable records. API Javadoc documents units, callback lifetimes and command outcomes. `StrategyContext` exposes market subscriptions, logical timers, borrowed quote/parent/child/effective-bound/reference views, frozen inception benchmark and submit/replace/cancel/status. `StrategyFactory.executionProfile` supplies engine-enforced permissions and benchmark requirements. A returned ACCEPTED result means the core reserved an intent, not that a venue accepted it. Observe `onOrderEvent` and handle rejection and partial fills.

## Writing a connector

Implement `ConnectorFactory` and register it in `META-INF/services/io.strategycontainer.api.ConnectorFactory`. Its factory receives destination capabilities, private settings and `ConnectorContext`. `Connector.send` runs outside the core. Normalize executions using stable execution and command identifiers; classify rejects correctly (risk/validation versus expected IOC/FOK liquidity outcomes). Retain uncertainty after ambiguous sends. Backpressure from quote/report sinks must be handled without silently losing financial reports. `subscribe` and `unsubscribe` run on connector I/O workers. Report online state separately from successful reconciliation. For internal booking, send an actual OMS request and report confirmed/uncertain outcomes; do not synthesize a venue fill.

`serve` requires explicit `.properties` configuration; see `Deployment` for required keys. Instruments define tick/lot/price scale, quantity unit and multiplier; destinations define order-type/TIF combinations, min/max sizes, protected peg/atomic replace/post-only/booking capabilities and connector provider name. Risk fields have no silent production defaults. Connector secrets under `connector.{destinationId}.*` are passed to the adapter and excluded from normalized journalling. The launcher does not supply a real asset-class connector.

## Development

Run `./gradlew test`, `./gradlew javadoc`, and `./gradlew formatJava` separately (format before compilation). Tests cover financial races, constraints, booking, recovery, journal corruption/truncation, replay, HTTP roles, concurrent producers, timer ordering and bounded event feeds. Java 21 is required. JUnit and the formatter are build-only dependencies. Keep business state transitions on the core, I/O on adapters, and externally observable changes as versioned journal inputs. Journal schema changes require a version/compatibility decision; do not silently reinterpret existing bytes.
